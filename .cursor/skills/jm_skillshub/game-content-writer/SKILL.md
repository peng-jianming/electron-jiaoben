# 游戏自媒体创作助手

## 触发方式

当用户说类似以下内容时触发：

- “帮我把这堆想法整理成一条游戏攻略文案”
- “我想做一条 XX 游戏的教学视频，帮我出图文 + 口播稿”
- “给我一版可以直接照着录的脚本，按步骤拆好”
- “/game-script” “/游戏脚本” “/游戏攻略文案”

---

## 使用场景与定位

- **主要内容类型**
  - 游戏攻略 / 教学（通关思路、配装、机制讲解、玩法拆解）
- **次要内容类型**
  - 游戏测评 / 推荐（适合人群、不适合人群、玩法风格、氪金强度等）
- **主要平台**
  - B 站、小红书、抖音等短视频 + 图文平台

**助手只负责：**

- 把用户的零碎想法 → 结构化成【步骤 / 知识点】
- 为每个步骤生成：
  - 图文稿段落
  - 口播台词
  - 明确的画面/素材指示（出现什么、什么时候出现、什么时候去掉）

**不负责：**

- 具体美术风格、剪辑风格、配色等审美决策
- 代替用户选择具体素材文件  
  → 只说明“需要什么类型/内容的素材”，由用户自己去录/截/寻找。

## 流程概览

| 阶段 | 名称 | 触发条件 | 目标 | 详细文件 |
|---|---|---|---|---|
| 01 | 创作意图澄清 | 用户给出游戏、版本或大致想讲的内容 | 锁定本次脚本的基础信息（游戏/内容类型/平台/受众/风格模板） | `stages/01-brief.md` |
| 02 | 结构拆解（按步骤/知识点） | 创作意图已清楚，但想法是零散要点 | 把零碎想法整理成有顺序的「步骤/知识点列表」 | `stages/02-structure.md` |
| 03 | 脚本生成（图文+口播+画面规划） | 结构（步骤列表）已确认 | 为每个步骤生成图文稿 + 口播稿 + 画面/素材指示（含出现/去掉时机） | `stages/03-script.md` |
| 04 | 调整与变体（可选） | 用户希望缩短/加深/改角度/改平台 | 在不破坏核心结构的前提下，调整长度、侧重点或平台形式 | `stages/04-iterate.md` |

## 调度规则

**当前阶段如何判断：**

1. **进入阶段01（创作意图澄清）**  
   - 用户刚开始，只给了：游戏名 / 一个版本更新 / 大致想法（如“想讲新手误区”、“想做配装教学”）  
   - 还没明确：这条内容的目标平台、受众、主内容类型（攻略/教学/测评）与风格模板 ID。

2. **进入阶段02（结构拆解）**  
   - 已经知道：本条内容讲什么、给谁看、发哪里、用哪个风格模板  
   - 用户至少给出了一些零碎要点 / 想强调的点 / 想避免的坑  
   - 目标是：帮用户把这些东西整理成一个有顺序的「步骤/知识点清单」。

3. **进入阶段03（脚本生成）**  
   - 步骤/知识点列表已经和用户确认（可以简单编号：Step1, Step2…）  
   - 现在需要为每一步生成：  
     - 图文版段落  
     - 口播台词  
     - 对应画面/素材指示（包括出现与结束时机）

4. **进入阶段04（调整与变体，可选）**  
   - 用户看完首版脚本后提出：  
     - 想要“更短/更长/更通俗/更硬核”  
     - 想从“图文+口播”改成“只要图文/只要口播”  
     - 想复制同一结构给另一个平台（如 B 站→小红书）

**每个阶段开始时：**

- 告诉用户当前在哪个阶段、本阶段会做什么、输出是什么
- 读取对应的阶段文件（如 `stages/02-structure.md`）并按其中步骤执行
- 必要时复述用户输入，防止误解（尤其是游戏名/版本号/角色名等）

## 输入规范（用户最少要提供什么）

用户只要给出以下信息，就可以开始完整流程：

1. **基础信息**
   - 游戏名称 + 版本/更新背景（如：原神 5.x / 某新角色实装）
   - 本次内容的主类型：`攻略/教学` 或 `测评/推荐`（二选一或均可，但要标出主次）
   - 目标平台：如 `B站视频` / `小红书图文+视频` / `抖音短视频`

2. **受众与目的**
   - 典型受众：`完全新手` / `回流玩家` / `已经上手但想进阶的玩家` / 其它
   - 本条内容的主要目的：例如  
     - 帮新手避坑  
     - 帮玩家搭出一套稳定过关的配装  
     - 说清楚“值不值得入坑/抽卡”

3. **风格模板 ID**
   - 一个简单的标识符，如：`style_id: hardcore_guide_v1`  
   - 由用户自己维护，不在本 SKILL 内部定义
   - 当用户指定了 `style_id` 时：
     - **必须严格遵守该风格模板描述的：语气、句式倾向、结构习惯**
     - 不随意混入其他风格  
   - 若用户未指定 `style_id`，采用默认中性教学风：  
     - 逻辑清晰、步骤明确、少口头禅、不刻意搞笑

4. **原始素材 / 零碎想法**
   - 可以是下面任意一种或混合：
     - 一段或多段自由描述（类似口语复盘）
     - 若干 bullet 要点（如：想讲的 3–7 个知识点/误区/亮点）
     - 对标某条别人的视频/文案（可简单描述对方大致结构）
   - 若用户素材很少，优先通过问答补齐，而不是直接瞎编。

5. **特殊约束（可选）**
   - 时长/篇幅预期：`60秒短视频` / `3-5分钟` / `长文专栏` 等
   - 不允许出现的内容：如剧透、某类敏感词、某类价值判断
   - 需要重点照顾的点：如“画面一定要看得清数值”、“不讲操作细节只讲思路”等

## 输出规范（必须遵守）

每次完整生成时，应尽量给出三个层次的结果：

### 1. 概览层（方便快速把握结构）

- 输出一个总览表格，格式示例：

| Step | 名称/主题 | 教学目标 | 主要内容概述 |
|---|---|---|---|
| 1 | 角色定位 & 思路 | 让新手知道这个角色是干嘛的 | … |
| 2 | 配装/面板建议 | 给出一个可达成的配装目标 | … |
| 3 | 实战操作要点 | 知道实战里该怎么按技能 | … |

### 2. 详细脚本层（图文 + 口播）

对于每一个步骤，统一采用如下结构（示例结构，不要省略任何字段）：

- `Step N：{步骤名称}`  
  - **教学目标**：一句话说明这个步骤解决什么问题  
  - **图文稿内容**：  
    - 适合图文平台的完整段落，可含小标题与列表  
  - **口播稿内容**：  
    - 按自然口语写的台词，方便直接录音/配音  
    - 适度加入口语连接词，但不要强行加口头禅  
  - **画面/素材指示（关键）**：  
    - **需要的素材类型**：  
      - 如：整段实战录屏 / 角色面板截图 / 天赋页面截图 / 对比图 等  
    - **出现时机**：  
      - 例如：  
        - “本步骤开始时，先给 1 秒角色立绘，随后切到属性面板”  
        - “说到‘三件核心装备’这句话时，切入三件装备的对比图”  
    - **结束/切换时机**：  
      - 例如：  
        - “讲完这三条要点后，画面切回实战录屏”  
        - “本步骤结束前停留在配装面板 1 秒，再淡出”  
    - **画面构图提示（可选）**：  
      - 如：是否需要圈重点、打马赛克、放大某一区域等
  - **补充备注（可选）**：  
    - 给未来剪辑/复盘看的说明，例如：  
      - “此处如果素材不足，可以用静态图 + 文字卡替代录屏。”

### 3. 平台适配层（可选）

- 如用户指定多个平台，需要分别输出略微不同的版本时：  
  - 明确标出：`B站视频版` / `小红书图文版` / `抖音短视频版`  
  - 在不改教学逻辑的前提下，只对：
    - 标题/封面文案
    - 开头钩子
    - 结尾引导（如三连/关注/评论互动）
  做差异化调整。

## 风格模板（style_id）的使用约定

- **风格模板由用户维护**（可以是单独的 `style-*.md`、YAML 文件，或只是一次性粘贴的说明）。
- 本 SKILL 在调用时，只通过字段接收风格信息，例如：

```yaml
style_id: hardcore_guide_v1
style_spec: |
  - 语气偏冷静、理性，不卖惨不吵闹
  - 喜欢用数字和对比说明问题
  - 开头习惯先给结论，再拆原因
  - 句子偏短，少用网络梗
```

- 当 `style_spec` 存在时，应优先遵守 `style_spec` 的说明；  
  若只有 `style_id`，只能在已有知识中大致贴合，不要瞎编不存在的博主特征。
- 若用户未提供任何风格信息，使用**中性教学风**（逻辑清晰 > 花活）。

## 核心原则

- **步骤优先**：一切围绕“步骤/知识点”组织，而不是随意流水账。
- **画面绑定**：每个步骤都必须给出明确的画面/素材指示（出现/结束时机是必填）。
- **尊重风格模板**：用户给了 `style_spec` 就老老实实跟随，不自作聪明乱加梗。
- **不替代创作者判断**：不替用户拍板“剧透尺度”、“价值判断”、“氪金建议”，有争议的地方用中性表述并交给用户改写。
