# 第四阶段：调整与变体（Iterate）

**目标：**  
在不推翻整体结构的前提下，根据用户的反馈，对已有脚本做：

- 长度调整（变短 / 变长）
- 平台适配（B 站 / 小红书 / 抖音 等）
- 角度微调（更新手向 / 更进阶 / 更测评）

---

## 使用前提

- `03-script` 已完成：已有一版可用的完整脚本（图文 + 口播 + 画面规划）；
- 用户给出了明确反馈，例如：
  - “太长了，想压到 60 秒”
  - “想做一个更详细的长文版”
  - “想多一个小红书图文版”
  - “想把重点从配装转到机制解释上”

---

## 步骤

### 1. 收集与澄清反馈

引导用户尽量具体地说出想要的变化：

- 长度相关：
  - 目标时长/篇幅（例如：60 秒 / 3–5 分钟 / 长文）
  - 更在意“信息全”还是“节奏快”
- 平台相关：
  - 需要适配的平台：B 站 / 小红书 / 抖音 / 其它
  - 是否要保留原平台版本不变，只生成新平台版本
- 角度相关：
  - 是否要更偏新手 / 更偏进阶
  - 是否要弱化/强化测评成分（比如少说“值不值”，多说“怎么玩”）

**输出要求：**

- 用一个简短小结把“本轮迭代的目标”写清楚，例如：  
  - “在不动整体结构的前提下，把整条内容压到约 60 秒，保留 3 个关键步骤即可。”

### 2. 决定保留/弱化/删除的步骤

基于用户的迭代目标，给出一个结构层面的调整建议：

- 对每个 Step 标注：
  - **强保留**：与本次目标强相关的核心步骤
  - **可压缩**：可以更快讲/略讲的步骤
  - **可删除**：在当前版本中可以舍弃的步骤

**输出要求：**

- 给出一份调整后的步骤总览表，清晰展示：
  - 哪些步骤被完全删除
  - 哪些被合并
  - 哪些只是缩短内容

### 3. 按需重写或缩写脚本内容

根据上一步的标注，对各步骤内容做差异化处理：

- 对于 **强保留** 步骤：
  - 若压时长：  
    - 保留核心论点和必要示例，删去重复铺垫；
  - 若拉长：  
    - 增加示例、解释、对比，保持逻辑清晰。
- 对于 **可压缩** 步骤：
  - 尽量改成“一两句总结式说明”，尤其在短视频版本中；
  - 图文版可以保留细节，口播版只说结论。
- 对于 **可删除** 步骤：
  - 直接在新版本中移除，但在备注中写明“原版中包含的内容”，方便未来复用。

### 4. 平台适配（如需要）

如果需要输出多个平台版本（例如 B 站视频版 + 小红书图文版），在**不改变教学主线**的前提下，对以下部分做调整：

- 标题与封面文案：
  - B 站：适度信息量 + 少量梗；
  - 小红书：更强调“怎么变好看/变强/避坑”；
  - 抖音：更短、更直接的痛点/爽点描述。
- 开头钩子：
  - 为每个平台调一个最适合它节奏的开头 1–2 句；
- 结尾引导：
  - B 站：适合“弹幕/讨论向”引导；
  - 小红书：适合“收藏/关注 + 提醒下次更新/系列内容”；
  - 抖音：适合“关注 + 引导看合集/系列”的轻量引导。

**输出要求：**

- 清楚标出当前输出属于哪个平台版本，例如：

```markdown
## 版本 A：B 站视频版（约 3 分钟）
……

## 版本 B：小红书图文版
……
```

### 5. 再次简要确认

- 将新版本的结构和关键变化点展示给用户；
- 明确标出与上一版相比：
  - 哪些内容被删减/弱化了；
  - 哪些地方增加了细节；
  - 哪些是平台级差异（只在某个平台版本出现）。

根据用户反馈，决定是：

- 继续微调当前版本；
- 还是就此作为定稿版本。

---

## 本阶段结束标志

- 至少生成了一个“满足迭代目标”的新版本脚本：
  - 长度、平台、角度与本轮目标相符；
- 用户能明确说出：
  - “这个版本我可以直接拿去录/去剪/去发”，
  - 上一版则可作为“完整版参考”保留。
