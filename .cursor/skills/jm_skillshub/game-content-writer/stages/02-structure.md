# 第二阶段：结构拆解（按步骤/知识点）

**目标：**  
把用户脑子里的零碎要点，整理成一份有顺序的「步骤/知识点列表」，每个步骤都清楚：要讲什么、解决什么问题、计划用什么类型的画面来辅助。

---

## 使用前提

- 已完成 `01-brief`：本次创作的游戏、版本、受众、平台、风格模板等信息已确认。
- 用户已经给出了一些原始素材/想法（可以很零散）。

---

## 步骤

### 1. 收集原始要点（允许杂乱）

- 请用户先不管顺序和结构，把想讲的点全部丢出来：
  - 想讲的知识点 / 技巧 / 误区
  - 一定要提醒的坑
  - 特别想夸/吐槽的设计
  - 和其它攻略不一样的观点
- 不要立即帮用户排序或打断，先完整记录。

**输出要求：**

- 用一个简单的无序列表，把这些要点逐条记下，保持用户原话风格为主。

### 2. 聚类与合并（从“点”到“块”）

- 在列表中，尝试按逻辑临近关系聚类，例如：
  - “角色定位 / 适合人群” 放一类
  - “配装/面板” 放一类
  - “实战操作/手法” 放一类
  - “常见误区/纠正” 放一类
  - “总结/抽卡是否值得” 放一类
- 对明显重复或高度相似的点进行合并，同时保留细微差异：
  - 例如：两个类似的误区可以合成“误区 A + 常见变体”。

**输出要求：**

- 给出若干个“内容块”，每块下面挂 2–5 条原始要点，示例：

```markdown
内容块 A：角色定位 & 适合人群
- 要点1：……
- 要点2：……
```

### 3. 设计步骤顺序（Step 1, 2, 3…）

基于上一步的“内容块”，和用户一起决定一个对目标受众最友好的顺序。常见顺序示例：

- 新手向攻略常用顺序：
  1. 这条视频/文章能帮你解决什么问题（钩子 + 价值）
  2. 角色/玩法的整体定位 & 适合人群
  3. 配装/面板怎么搭，给一个“够用就行”的推荐线
  4. 实战里怎么按键 / 怎么处理常见情况
  5. 常见误区 & 纠正
  6. 总结 & 行动建议（比如“先练到几级，再考虑进阶配装”）

- 测评/推荐类常用顺序：
  1. 结论/定位（值不值得抽/玩）
  2. 优点亮点
  3. 缺点和需要接受的点
  4. 适合谁 / 不适合谁
  5. 如果要入坑，推荐的玩法路线

**输出要求：**

- 把每个“内容块”排到一个 `Step N` 下，并写出：
  - 暂定的步骤名称
  - 该步骤的大致教学目标

示例：

```markdown
Step 1：这条内容到底帮你解决什么
- 教学目标：让新手知道看完之后能得到什么具体好处

Step 2：这个角色/玩法适合什么样的玩家
- 教学目标：帮观众判断自己要不要继续看/要不要练
```

### 4. 为每个步骤标记“画面需求粗框”

此时不需要写具体台词，只需要粗略标记每个步骤可能会用到的画面类型，帮助后续脚本生成阶段更高效：

- 对每个 `Step N`，回答三个问题：
  - 这一步 **最适合** 用什么素材承载？（实战录屏 / 面板图 / 文本卡片 / 对比图 / 角色立绘 等）
  - 有没有 **必须出现** 的关键画面？（例如：关键数值面板、天赋树、某个机制演示）
  - 有没有 **可以只用静态图代替录屏** 的地方？（方便节省录制成本）

**输出要求：**

- 在每个 `Step` 下增加一个小节，类似：

```markdown
Step 2：这个角色适合什么样的玩家
- 教学目标：帮观众判断自己要不要练
- 画面需求粗框：
  - 建议素材：角色立绘 + 两种典型队伍配图
  - 必须出现：角色在队伍中的站位截图
  - 可选替代：如果没有实战录屏，可以用文字卡 + 配队示意图代替
```

### 5. 和用户确认最终步骤列表

- 把整理好的步骤列表（含：步骤名称 + 教学目标 + 画面需求粗框）整体展示给用户。
- 邀请用户检查：
  - 顺序是否 OK？
  - 有没有缺少的关键步骤？
  - 有没有不必要的步骤可以删掉或合并？

**输出要求：**

- 标记版本号或时间（方便以后复用此结构）。
- 明确说明：“如果你确认没问题，我们就根据这个步骤列表进入下一阶段，生成图文 + 口播 + 画面规划的详细脚本。”

---

## 本阶段结束标志

- 已经有一份清晰的 `Step 1, 2, 3…` 列表；
- 每个步骤至少包含：
  - 步骤名称
  - 一句话教学目标
  - 粗略的画面需求说明；
- 用户明确表示“OK，可以按这个结构写脚本了”。
