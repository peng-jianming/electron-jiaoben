# 第一阶段：创作意图澄清（Brief）

**目标：**  
在不卷细节的前提下，把本次脚本的「基本盘」问清楚：游戏是什么、这条内容是干嘛的、给谁看、发到哪、用什么风格模板。

---

## 步骤

### 1. 确认基础信息

依次向用户确认以下信息（用聊天语气，自然地问）：

- 游戏名称 + 版本/活动背景  
  - 例：原神 5.x / 某某新角色实装 / 某某活动副本
- 本次内容的主类型  
  - 攻略/教学 为主，还是 测评/推荐 为主（可以有“主 + 次”）
- 目标平台  
  - 如：B 站视频、小红书图文+视频、抖音短视频 等

**输出要求：**

- 用一个小表格/列表，汇总用户回答，方便后续引用。

### 2. 确认受众与创作目的

引导用户具体化「给谁看」和「看完要有什么变化」：

- 受众典型画像（可多选）：
  - 完全新手
  - 回流玩家
  - 已经上手但想进阶的玩家
  - PVP/PVE 向玩家（视游戏而定）
  - 其它（让用户自己描述）
- 本条内容的主要目的：
  - 帮新手避坑
  - 给出一套可复制的过关思路/配装方案
  - 让观众判断“值不值得入坑/抽卡/购买”
  - 解释某个复杂机制，让人一下子懂

**输出要求：**

- 明确写出一句话的「创作目的总结」，例如：  
  - “让刚抽到 XX 的新手，在 3 分钟内弄明白怎么配装 + 怎么打主流本。”

### 3. 确认时长 / 篇幅预期（如果用户有想法）

简要询问用户对整体长度的偏好：

- 例如：
  - `60 秒短视频`
  - `3–5 分钟攻略`
  - `长文专栏`
- 若用户“不确定”，则：
  - 给一个默认方案（如 3–5 分钟 / 中等长度图文）
  - 标记为“可在后续阶段调整”。

### 4. 确认风格模板（style_id / style_spec）

这里不讨论“好不好看”，只要把“风格约束”记录清楚，后面统一执行：

- 询问用户：
  - 是否有现成的 `style_id`（例如：`hardcore_guide_v1`）
  - 是否愿意临时粘贴一段 `style_spec`（语气、句式、结构习惯说明）
- 如果两个都没有：
  - 告诉用户将使用 **“中性教学风”** 作为默认风格：
    - 逻辑清晰、步骤明确、少口头禅、不刻意搞笑。

**输出要求：**

- 用一个代码块记录本次的风格约束，例如：

```yaml
style_id: hardcore_guide_v1
style_spec: |
  - 语气偏冷静、理性，不卖惨不吵闹
  - 喜欢用数字和对比说明问题
  - 开头习惯先给结论，再拆原因
  - 句子偏短，少用网络梗
```

若用户只给了 `style_id`，则只记录 `style_id` 字段并标注“未提供详细 spec”。

### 5. 收尾小结

在结束本阶段前，给出一个「创作意图总览」，包含：

- 游戏 + 版本/活动
- 内容主类型（攻略/教学 or 测评/推荐）
- 目标平台
- 受众画像
- 创作目的一句话
- 预期长度
- 风格约束（style_id / style_spec）

格式可以是简短小节或小表格，保证后续阶段可以直接引用，不需要再次追问以上信息（除非用户主动修改）。
