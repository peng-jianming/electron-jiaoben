# Agent 项目沟通说明（SKILLS.md）

用于让 Agent 在改代码/加功能时，能快速定位：**改哪里、怎么连前后端、怎么新增任务、以及新增事件该走哪条链路**。

---

## 1. 项目一句话

这是一个基于 **Electron + Vue3** 的客户端（负责界面、与后端中转/通信），配套 **Python** 自动化脚本后端（负责 ADB/截图/图色识别/点击滑动/按任务状态机执行）。

---

## 2. 目录分工（按“职责”找代码）

1. `frontend/`
   - Vue3 页面与交互（账号/设备/任务配置）。
   - 向 Electron 发送 IPC 指令：调用 `ipc.invoke(ipcApiRoute.发送到后端, { 类型, ...extra })`。
   - 监听后端 Socket.IO 推送事件：`backend-ready`、`device-list`、`task-list`、`account-list`、`account-status-update`。

2. `electron/`
   - Electron 主进程/预加载（`electron/main.js`、`electron/preload/*`）。
   - Socket.IO Server（端口 `7072`）与“事件转发”中转层（`electron/controller/example.js`）。
   - IPC 路由通道定义在 `frontend/src/api/index.js`，具体处理在 `electron/controller/example.js`。

3. `python/`
   - 后端入口：`python/index.py`
   - 通信：`python/core/通信管理器.py`（Socket.IO Client，收到前端 `message` 后按 `类型` 分发）
   - 任务发现与执行：`python/core/任务管理器.py`（扫描 `python/任务/*.py`，按文件名当任务名）
   - 图色/识别/点击：`python/core/动作管理器.py`、`python/core/界面管理器.py`
   - 资源路径与端口：`python/设置.py`

---

## 3. 前后端通信协议（最关键）

### 3.1 前端 → 后端（命令下发）

- 前端在 `frontend/src/views/Index.vue` 中，封装函数：
  - `sendToBackend(类型, extra)` → `ipc.invoke(ipcApiRoute.发送到后端, { 类型, ...extra })`
- IPC 路由通道定义在 `frontend/src/api/index.js`：
  - `发送到后端: 'controller/example/发送到后端'`
- Electron 中转实现（`electron/controller/example.js`）：
  - `发送到后端(args)` 会执行 `socketServer.io.emit('message', args)`

因此：**Python 收到的 Socket.IO `message` 数据结构，必含 `类型` 字段**（其它字段随类型不同）。

### 3.2 后端 → 前端（状态推送 / 列表下发）

- Python 在 `python/core/通信管理器.py` 中通过：
  - `发送到Electron(事件名, 数据)`
  - 发送 Socket 事件：`socket-channel`，payload 里包含 `cmd: controller/example/从后端接收数据` 与 `args: { 事件名, 数据 }`
- Electron 的 controller 处理（`electron/controller/example.js`）：
  - `从后端接收数据(args)` 取出 `args.事件名`，并执行 `socketServer.io.emit(事件名, 数据)`
- 前端在 `frontend/src/views/Index.vue` 里监听对应事件名：
  - `backend-ready`
  - `device-list`
  - `task-list`
  - `account-list`
  - `account-status-update`

## 4. `类型` 字段有哪些（Python 入口分发表）

后端入口：`python/index.py`，在 `客户端消息队列处理(self, 类型, 数据)` 内维护映射。

Agent 新增“前端按钮/菜单动作 → 后端执行逻辑”时，通常需要：
1. 在 `frontend/src/views/Index.vue` 调 `sendToBackend(新类型, extra)`
2. 在 `python/index.py` 的 `处理器` 字典里加上 `新类型: 对应函数/lambda`
3. 在需要向前端更新时，调用 `self.通信管理器.发送到Electron(事件名, 数据)`（或走 `更新账号数据()` / 设备池回调）

当前已支持的类型（来自 `python/index.py`）：

1. `打开日志`：`数据 = { 账号 }`
2. `获取设备列表`：无额外字段
3. `获取任务列表`：无额外字段（会下发 `task-list`，内容为任务名列表）
4. `获取账号列表`：无额外字段
5. `设置账号任务配置列表`：`数据 = { 账号, 任务配置列表 }`
6. `禁用设备`：`数据 = { 设备ID }`
7. `启用设备`：`数据 = { 设备ID }`（启用后可能触发等待队列继续）
8. `账号开始任务`：`数据 = { 账号, 任务配置列表 }`（可能分配设备或进入等待队列）
9. `账号结束任务`：`数据 = { 账号 }`
10. `账号暂停任务`：`数据 = { 账号 }`
11. `账号恢复任务`：`数据 = { 账号 }`
12. `全部开始`：`数据 = { 任务配置列表 }`
13. `全部结束`：无额外字段
14. `全部暂停`：无额外字段
15. `全部恢复`：无额外字段

前端实际调用点（供 Agent 对照）在 `frontend/src/views/Index.vue`：
- 获取列表：`获取设备列表` / `获取任务列表` / `获取账号列表`
- 账号操作：`账号开始任务` / `账号结束任务` / `账号暂停任务` / `账号恢复任务` / `打开日志`
- 设备操作：`启用设备` / `禁用设备`
- 批量操作：`全部开始` / `全部暂停` / `全部恢复` / `全部结束`

## 5. 新增任务（Task）怎么做

后端任务发现机制：`python/core/任务管理器.py`
- 会扫描 `python/任务/` 下所有 `.py` 文件
- **文件名（去掉 `.py`）即任务名**
- 每个模块必须提供 `创建任务(环境)` 函数（可被 `importlib` 导入）

新增任务的 Agent 操作路径（通常三步）：

1. 新建任务脚本：`python/任务/<任务名>.py`
   - 必须实现：`def 创建任务(环境): ...`
   - 创建 `任务界面状态机 = 任务界面状态机类(环境)`
   - 用 `@任务界面状态机.注册界面("<界面名>")` 注册界面状态逻辑
   - 最后调用：`任务界面状态机.开始()`
   - 若需要公共界面逻辑可使用 `@任务界面状态机类.注册全局界面("<界面名>")`
   - 任务级参数读取：从 `环境.参数配置` 取值（参数来自前端保存的 `任务配置列表`）

2. 确保 UI 能看到任务（列表自动）：无需在后端手工注册
   - 前端会在 `backend-ready` 后调用 `获取任务列表`
   - 后端会把 `任务管理器类.获取所有任务列表()` 的 keys 通过 `task-list` 推给前端

3. 若该任务需要配置项：更新前端 schema
   - 文件：`frontend/src/components/Task.vue`
   - 常量：`TASK_CONFIG_SCHEMA`
   - 规则：`TASK_CONFIG_SCHEMA` 的 key 必须与 `<任务名>` 完全一致
   - 支持字段类型：`number` / `text` / `select` / `checkbox`

> 若任务名不在 `TASK_CONFIG_SCHEMA` 中：前端仍会显示任务，但配置区会提示“无需配置/空配置”（默认空参数配置）。

## 6. 新增/修改“界面识别与按钮点击”

界面识别与按钮/状态的结构，主要来自资源配置：
- `python/设置.py` 定义：`界面配置文件路径 = python/资源/界面配置.json`
- `python/core/任务管理器.py` 会把界面配置加载成 `界面集合`
- `python/core/界面管理器.py` 会根据配置动态创建：
  - `界面.按钮.*`（动作：识别 + 点击/延时等）
  - `界面.状态.*`（动作：识别 + 点击等或状态判断）
  - `界面.滑动区域.*`
  - `界面.识字区域.*`（OCR 区域）

因此：
- 只是改“某个按钮在屏幕上应该怎么找/点击/相似度/偏移”等：优先改 `python/资源/界面配置.json`
- 需要改“任务流程/状态机怎么走/何时切界面/何时结束任务”：改 `python/任务/<任务名>.py`

## 7. 运行与调试要点（Agent 排错清单）

1. 前端页面显示 `等待后端`：
   - 检查后端 Socket.IO Client 是否连接到 `http://127.0.0.1:7072`
   - 检查 Electron socketServer 是否在 `7072` 且 `channel: 'socket-channel'`（`electron/config/config.default.js`）

2. 前端能连上但收不到列表：
   - 确认 `backend-ready` 是否触发
   - 如果触发了但 `task-list/device-list/account-list` 不更新，通常是后端对应 handler 没走到或发送事件名写错

3. 新增任务后任务列表仍看不到：
   - 检查任务文件是否在 `python/任务/`
   - 检查该文件是否实现了可调用的 `创建任务`
   - 检查任务名是否被前端 schema/任务配置表引用（schema 不影响任务出现，只影响是否显示配置项）

4. 任务执行但识别不到按钮/状态：
   - 优先检查 `python/资源/界面配置.json` 内该界面的 `查找字符串/查找区域/点击区域/相似度/误触区域` 等字段

## 8. 任务运行模型（界面 = 瞬时状态）

- **整体入口链路**：
  - Electron 收到“开始任务”类指令 → Python `主程序.账号开始任务()` 分配设备 → `线程控制器` 为该账号起线程 → 线程里实例化 `任务管理器类`。
  - `任务管理器类.__init__` 中：
    - 解析参数（设备ID / 任务配置列表 / 更新数据回调等）
    - 初始化控制器 / 截图上下文 / 字库 / 图片库 / 界面集合等
    - 最后调用 `self.运行()`，按「任务配置列表」依次执行每个任务。

- **单个任务的构造**：
  - `任务管理器.运行()` 对当前账号的 `任务配置列表` 循环：
    - 每个 `任务配置` 通过 `任务管理器类.获取所有任务列表()` 找到对应模块的 `创建任务(环境)` 函数
    - 创建 `状态机环境`（包含：控制器、界面集合、截图上下文、界面识别缓存、更新数据回调、参数配置）
    - 调用该任务模块的 `创建任务(环境)`，任务模块内部会：
      - 创建 `任务界面状态机 = 任务界面状态机类(环境)`
      - 通过多个 `@任务界面状态机.注册界面("某界面名")` 注册「该界面进入时要做的一步原子操作」
      - 最后调用 `任务界面状态机.开始()` 进入状态机主循环。

- **核心思想：每个“界面”是一个瞬时状态，函数只做“一步原子操作”**：
  - `任务界面状态机.开始()` 内部是一个永不停止的 `while self.任务未完成:` 循环，大致逻辑：
    1. 重置截图上下文，获取当前一帧截图。
    2. **识别当前界面**：
       - 优先尝试「当前界面 / 上一界面」以提高稳定性与性能；
       - 然后遍历所有已注册界面（`self.注册界面集合`）；
       - 通过 `界面识别缓存[界面名称].查找().是否找到()` 判断是否命中。
    3. 一旦识别出某个界面：
       - 先执行全局公共处理器（`_全局界面公共处理器集合`）
       - 再执行当前任务实例的“所有界面公共逻辑”（`_当前任务所有界面公共处理器`）
       - 最后执行 **该界面专属函数**：即用户在任务脚本中通过 `@任务界面状态机.注册界面("X界面")` 注册的那一个。
    4. **界面函数只做“一步原子操作”，然后立即返回**：
       - 例如：点击一个按钮（`界面.按钮.XXX.找到则点击(...)`）或滑动一次（`界面.滑动区域.活动面板.按循环滑动(...)`）；
       - 或通过状态判断决定是否调用 `任务界面状态机.结束()`（结束当前任务）、或者只更新日志/上下文；
       - 执行完毕后不再自己写循环，而是 **直接 return，让控制权回到 while 顶层**。
    5. 顶层 while 下一轮会重新截图、重新识别界面、重新决策下一步原子操作。

- **这样设计的意图（给 Agent 的约束）**：
  - 避免在单个界面处理函数里写长循环或多步序列逻辑，防止「识别状态滞后」「点错界面」。
  - 所有复杂流程都拆成「多轮：识别 → 单步原子操作 → 退出 → 重新识别」，保证每一步都在最新界面/最新截图上决策。
  - Agent 在修改/新增任务脚本时，应 **遵守以下约定**：
    - 不要在单个 `@任务界面状态机.注册界面` 的函数里写 `while True` 之类的小循环；
    - 一次只做一件事（一个点击或一段滑动/一次判断），做完后直接 `return` 或结束状态机；
    - 如需“多次滑动/多次重试”，优先通过：
      - `界面.滑动区域.按循环滑动(上下文, 计数键, 每阶段次数, 日志)` 这类封装
      - 或使用 `上下文` 中的计数器，在多次进入该界面时分批执行。
